# bases/ デザイン・レイアウトの基準（要約）

`bases/` のデザイン・レイアウトの基準の元になるファイルです。基準を変えるときは、まずこのファイルを書き換え、それに合わせて `bases/` のHTMLと `base.css` を直します。HTMLと食い違うときは、このファイルを正とします。デザインやレイアウトを揃えるときもこのファイルを読み、見本の見た目や操作を確かめるときだけHTMLを開きます（ADR-0008）。

| ファイル | 内容 |
| --- | --- |
| `base.css` | 共通CSSの編集元。各HTMLに埋め込む（ブラウザは読み込まない） |
| `sync_styles.mjs` | `base.css` を各HTMLへ反映するスクリプト |
| `display.html` | 画面構成と操作：タブ・Vim操作・作業領域の幅・実装ルール |
| `atomic_component.html` | デザイン要素：配色・アイコン・文字・操作部品・形と余白・記号の意味 |
| `color.html` | `tome.jpg` の代表色とカラーコード（HEX・RGB）の説明 |
| `tome.jpg` | 配色とパズルモチーフの元画像（576×576px） |

## 実装ルール

- 各HTMLは1ファイルだけで表示・操作できるようにする。外部CSS・外部JavaScriptは読み込まず、`<style>`・`<script>` をHTML内に書く。表示に必要な画像も埋め込む。
- 資料間のリンクや、利用者が選んで読み込むJSONは別ファイルでよい。ブラウザ内保存のデータを別環境へ移すときはJSONの書き出し・読み込みを使う。
- 印刷スタイルも各HTML内に定義する。
- 共通CSSは `<!-- bases:styles:start -->`〜`<!-- bases:styles:end -->` の範囲に埋め込む。範囲内は同期で上書きされるので直接編集しない。共通の変更は `base.css`、ページ固有のCSSは範囲外の `<style>` に書く。
- 同期の対象は、リポジトリ直下と `bases/` 直下のHTML。新しいHTMLにもマーカーを1組置く。
- `node bases/sync_styles.mjs`：反映 ／ `--check`：確認だけ（未反映があれば終了コード1）／ `--watch`：保存時に自動反映。

## 部品と形

- **マーク**：`.mark`（15×15px、角丸3px、深緑、`box-shadow: 5px -5px 0 var(--brown)`）。1個のspanで描き、`aria-hidden="true"` を付ける。文字との間はgap 10px。
- **書体**：本文はOS標準のサンセリフ（`-apple-system, BlinkMacSystemFont, "Helvetica Neue", "Hiragino Kaku Gothic ProN", "Noto Sans JP", Meiryo, sans-serif`）、コード・数値は等幅（`ui-monospace, SFMono-Regular, Consolas, monospace`）。外部Webフォントは使わない。
- **文字サイズ**：Eyebrow 11px/700/字間.2em/茶色、H1 `clamp(32px, 4.5vw, 51px)`、H2 23px（720px以下は20px）、本文14px/行間1.85/Muted、節番号13px等幅。
- **角丸**：3px マーク ／ 5px ボタン・画像 ／ 9px 色カード ／ 12px 図・操作パネル ／ 16px 画像フレーム。
- **面**：浮き上がる影は付けない。背景色と1pxの線でまとまりを示す。
- **ボタン**：小さなボタンは透明背景・深緑の文字・1px線・角丸5px。主操作は深緑の塗りと白文字。無効なボタンは薄く表示する。
- **スライダー**：`accent-color: var(--green)`。

## タブ

- 案件・モデル・図など、ひとまとまりの作業を1つのタブに分け、内容や表示状態をタブ単位で扱う。
- デザインは `outline.html` のタブが基準。編集領域の上に置き、塗り・外枠を付けない。選択中は深緑・太字・タブ全体の下辺線で示し、文字に下線は付けない。
- タブ名の前に `00`、`01`… と2桁の番号を付け、数字だけ茶色（選択中・編集中も茶色）。番号は表示順で、追加・削除後に振り直す。保存するタブ名に番号は含めない。
- タイトル（切り替え）と「×」（確認してから削除）をひとまとまりにし、右端の「＋」で追加する。増えたら折り返さず横スクロールにする。
- `base.css` の `[role="tab"][aria-selected="true"]` は既定で深緑の塗り・白文字・下線になる。outline型のタブは、ページ固有CSS（`.work-tabs` など）で上の見た目に上書きする。

## Vim操作（オブジェクト整理の例）

入力欄からEscで抜けると使える。マウスと併用でき、選択位置とフォーカスを画面に示す。文字入力中・日本語変換中は入力を優先する。キーの意味はツールごとに異なる。

| キー | 動作 |
| --- | --- |
| `j` / `k` | 次／前の項目を選択 |
| `h` / `l` | 参照元／参照先へ移動 |
| `i` / `e` | 追加／選択項目の名前を編集 |
| `t` / `Shift+t` | 次／前のタブへ |
| `z` / `o` | カードの開閉／選択項目と関係先に集中・解除 |
| `f` | 全画面の切り替え |
| `u` / `Ctrl+r` | 元に戻す／やり直す |

## 画面の幅

- 中央の作業領域を広く取り、ナビゲーション・詳細・補助操作が幅を取りすぎないようにする。説明文は読みやすい行長（本文は最大76ch）に抑え、図や表は横幅を活かす。
- 補助パネルは開閉でき、狭い画面では縦に並べる。
- 集中表示は「何を見るか」を絞り、解除で全体に戻る。全画面は「どの広さで見るか」を広げる。
- `base.css` の `body[data-layout]`：`sheet`（header・main・footerを幅 `100% - 48px`）、`document`（サイドバー220px＋本文、最大1440px）、`workspace`（編集画面の折り返しと幅の調整）。900px以下・760px以下で段階的に狭める。

## 記号の意味

| 記号 | 意味 |
| --- | --- |
| ＋ | 追加（タブ横はタブ、項目横はその項目の直後に同じ階層で追加） |
| × | タブ・行などの横では削除（タブは内容も削除）。ダイアログの端では閉じる |
| ◎ | 選択項目に集中（キー `o`）。「集中を解除」で全体に戻る |
| 四隅を広げた形 | 全画面（キー `f`） |
| ☰ | 補助パネルの開閉（閉じても内容は消えない） |
| ▸ ▾（▶ ▼） | 折りたたみ／展開（キー `z`） |
| ⠿ | ドラッグで順序・階層・配置を変える |
| ↑ ↓ ← → | 順序や階層の移動、図では流れ（実線：作業・情報の受け渡し、点線：参照・帳票） |
| ‹ › | 前・次（月・週・列など） |
| ✓ | 完了（アウトラインでは完了／未完了の切り替え） |
| ◆ | 完了予定日（✓とは区別する） |
| ↗ / ↓ / ↑ | 別資料へ／後の説明へ／先頭へ |

- **フォーカス**（茶色の輪郭）：いまキーが届く場所。**選択**：どの作業を対象にするか。**集中**：いま見る範囲を絞る。3つを見た目で区別する。
- 表示切り替え（「月／週」など）は同じ内容の見せ方を変えるもので、作業タブとは別。
- 読み込み（ファイルから）・JSON保存（ファイルへ）・コピー（クリップボードへ）・ブラウザ内の自動保存は、保存先が違う。

## アクセシビリティ

- アイコンだけのボタンにも `aria-label` で操作名（「タブを追加」など）を付け、必要なら `title` で補足する。削除ボタンの名前には対象を含める。
- 状態は `aria-expanded`（開閉）・`aria-pressed`（切り替え）・`aria-selected`（選択中のタブ）で伝える。
- フォーカスは `:focus-visible` の輪郭で示す。`prefers-reduced-motion` ではスクロールのアニメーションを止める。

## このファイルの更新

基準（色・部品・ルールなど）は、次の順に直す。同じ作業の中で最後まで進め、途中の段から始めない。

```text
bases/README.md            1. 基準を書き換える（ここが正）
  ↓
bases/base.css             2. 共通CSSに関わる場合だけ直し、node bases/sync_styles.mjs を実行
  ↓
bases/*.html（影響あるもの） 3. 説明・見本・ページ固有のCSSを直す
  ↓
*.html（影響あるもの）      4. リポジトリ直下のページ固有のCSS・部品・操作を直す
```

- 2の同期で、すべてのHTMLの共通CSSの範囲は自動で更新される。3・4では、範囲外のページ固有のCSS・HTML・JavaScriptを直す。
- 影響がない段は飛ばしてよい。最後に `node bases/sync_styles.mjs --check` を実行する。
