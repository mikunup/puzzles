使い始める

目的に合うHTMLを選んでください。下の資料リンクはすべて別タブで開きます。

業務定義 ↗→業務の流れ ↗→オブジェクト ↗→画面設計 ↗→単体テスト ↗

業務を整理し、必要な情報をまとめ、画面の表示・操作とテストへ具体化します。計画書とカレンダーは、各工程の計画・実施状況の整理に使います。

業務を整理する

業務定義シート ↗

business_definition_sheet.html

業務の目的・担当・入力情報・作業内容・成果物を整理し、業務ごとの定義シートを作成します。

使い方・機能：シートの追加・入力、ブラウザ内保存、JSON読み込み／書き出し、印刷・PDF。

業務シーケンス図 ↗

business_sequence.html

情報項目／ステータスと、みるもの（担当・外部）のマトリクスに作業・帳票を置き、矢印でつないで業務の流れを整理します。

使い方・機能：未配置オブジェクト（作業・帳票）の一括追加、同じIDでの配置・配置解除、別IDへの複製、複数タブで図を編集、Vimキー操作、全画面・集中表示、元に戻す／やり直す、ブラウザ内保存、JSON読み込み、全タブJSON保存・復元、JSON／Markdown／HTML書き出し（行・列の意味を含む）、印刷・PDF。

オブジェクト整理 ↗

object_model.html

オブジェクトの名前・プロパティ・操作を整理し、シングルとコレクションの表示項目・操作を設計します。

使い方・機能：複数タブ、Vimキー操作、全画面・集中表示、Enum型の保存値・表示名・初期値設定、オブジェクト・コレクションの編集、参照関係図・マトリクス・関係一覧、ブラウザ内保存、JSON読み込み／書き出し・全タブ保存。

画面を設計・テストする

画面・機能設計書 ↗

screen_design_template.html

Web自動販売機を例に、画面一覧・遷移、オブジェクト、データ・権限、画面要素、操作、検証と結果を定義します。

使い方・機能：設計例を参照し、HTML内の内容を編集して自分のシステムの設計書に使います。見本の購入・保存は実行しません。

画面単体テストケース ↗

screen_unit_test.html

画面グループごとに「目的 → 前提 → ケース表」を読み、正常・バリデーション・異常を確認します。

使い方・機能：OK／NG・保留の記録、実績メモ、集計、ブラウザ内保存、結果のJSON書き出し。自動テストの実行ページではありません。

計画・スケジュールを整理する

アウトライン ↗

outline.html

見出しとタスクを階層で整理し、必要な項目に集中します。

使い方・機能：アウトライン／ロジックツリー切替、複数タブ、パネル開閉、折りたたみ、ドラッグで上下左右に移動、集中表示、自動保存、JSON／Markdown読み込み・書き出し。

スケジュール計画書 ↗

schedule_plan.html

プロジェクトの目的・マイルストーン・ガントチャート・WBS・体制・リスクをまとめます。

使い方・機能：HTML内の内容を編集して、プロジェクト計画・役割分担・進捗報告の資料に使います。

カレンダースケジュール ↗

calenderschedule.html

カレンダーに予定や工程を入力し、ガントチャートやマトリクスシーケンスで確認します。

使い方・機能：予定の追加・編集、表示切り替え、ブラウザ内保存。

使い方・機能：共通デザインを再利用する時の参照資料。

画面構成と操作の考え方 ↗

bases/desplay.html

タブの概念、Vim操作、メインのタスクに集中できる広い作業領域の考え方を説明します。

共通デザインの適用

全13ページはbases/base.cssを読み込み、配色・フォーカス表示・タブの選択表示を共通化しています。HTMLを移動・配布する場合は、共通CSSを含むbases/も相対パスを保って配置してください。

  • 編集画面：業務シーケンス図・オブジェクト整理・アウトラインは全幅の作業領域を使います。業務定義シート・カレンダー・スケジュール計画書も画面幅を活かして表示します。
  • 資料画面：資料一覧・説明資料の雛形・画面設計書・画面単体テストは、本文の領域を最大1440pxのレイアウト内で広く確保し、狭い画面では目次と本文を縦に並べます。
  • タブ操作：タブにフォーカスした状態で左右矢印・Home・Endを使えます。業務定義シートはシート、カレンダーは表示方法、業務シーケンス図・オブジェクト整理・アウトラインは作業を切り替えます。
  • Vim操作・集中表示・全画面：業務シーケンス図・オブジェクト整理・アウトラインで利用できます。キーの意味は各ページの操作ヘルプを確認してください。アウトラインのパネル開閉はタイトル横から操作できます。
  • 印刷：画面用の幅変更は印刷に適用せず、各ページの印刷用レイアウトを使用します。

編集と保存

  • 編集ツールのページ：業務定義シート・業務シーケンス図・オブジェクト整理・カレンダー・アウトラインは、画面内で内容を入力します。
  • 資料のページ：画面設計書・スケジュール計画書・説明資料の雛形は、HTML内の文章や表を書き換えて使います。
  • テストの記録：画面単体テストケースは、画面内で実施結果とメモを入力できます。
  • ブラウザ内の保存：データは端末間で自動共有されず、HTMLファイル自体にも書き戻されません。別のブラウザや保存場所では同じ記録を参照できない場合があります。
  • 書き出し：JSON機能があるページでは、受け渡しや控えに書き出しを使います。読み込み機能の有無は各ページのボタンを確認してください。

ローカルデータの管理

  • datas/：ローカルにダウンロードしたJSONや、各ツールから書き出したデータなどを追加して保存・管理するディレクトリです。必要に応じて、各ページのJSON読み込み機能で利用します。
  • .gitignore：Gitの管理対象から除外するパスを指定するファイルです。/datas/を指定し、このリポジトリ直下のdatas/とその配下のファイル・サブディレクトリを除外しています。
  • datas/内のデータはコミット・共有されません。新しくクローンした環境では、必要に応じてdatas/を作成し、データを配置してください。README.mdのdatas/へのリンクは、対応するファイルをローカルに配置した場合に利用できます。
