ADR-0004：業務定義シートとアウトラインの共通CSSを、共通デザインに揃える

business_definition_sheet.html と outline.html の共通CSSの範囲に残っている独自の書き換えを取り除き、node bases/sync_styles.mjs で base.css と一致させる。タブの見た目は、範囲外のページ固有CSS（.work-tabs）がすでに決めているため変わらない。

01 /

背景・課題

Issue #2 のとおり、business_definition_sheet.html と outline.html は共通CSSの範囲（<!-- bases:styles:start -->〜<!-- bases:styles:end -->）の中身が直接書き換えられており、デザインの共通化ができていない。base.css を変えてもこの2ページには反映できず、node bases/sync_styles.mjs --check では2ページが常に「未反映」と表示される。

調べたところ、書き換えはコミット 79ead33（2026.11.08「タブ情報の位置を調整」）で入ったものだった。同じコミットで、作業画面の下段タブの見た目（.work-tabs）が各ページの範囲外のCSSに追加されている。business_flow.html・calenderschedule.html・object_model.html は範囲外だけを変えており、この2ページだけが範囲内も書き換えていた。

現状

  • business_definition_sheet.html：選択中のタブの下線をなくす指定と、シートタブ（.sheet-tab）を選択時に緑で塗る指定が範囲内にある。
  • outline.html：タブ番号（.tab-number）を茶色にする指定と、タブ列を伸ばさない指定（flex: 0 1 auto）が範囲内にある。
  • 2ページとも、範囲外に .work-tabs の指定（下線で選択を示す・番号を茶色・タブ列を伸ばさない）があり、範囲内の指定より優先度が同じか高く、後ろに書かれている。

制約・前提

  • 各HTMLは1ファイルで動き、共通部分は base.css から同期する（README.md「共通デザインの適用」）。
  • 共通CSSの範囲は同期で上書きされるため、ページ固有のCSSは範囲外に書く。
  • 利用者が見ているタブの見た目は変えない。
この ADR で決めること2ページの共通CSSの範囲に残る独自の書き換えをどう扱い、共通デザインに揃えるか。
02 /

判断基準

  1. 共通デザインの仕組みに沿うこと

    範囲内を base.css と一致させ、base.css の変更が全ページに届くようにするため。

  2. 今のタブの見た目を変えないこと

    作業画面のタブは利用者が毎日触る部分で、意図しない見た目の変化を避けるため。

  3. 変更が小さく、確認しやすいこと

    変更の範囲を2ページの範囲内に限り、影響を確かめやすくするため。

選択肢ごとの詳細

選択肢 A：同期して共通デザインに揃える

node bases/sync_styles.mjs を実行し、2ページの範囲内を base.css で上書きする。範囲内の独自の指定は、範囲外の .work-tabs の指定に上書きされていて効いていないため、取り除く。

良い点
範囲内が base.css と一致し、--check が通る。タブの見た目は変わらない。手作業がない。
懸念点
下段タブの見た目が各ページの範囲外に重複して書かれている状態は残る。

選択肢 B：下段タブの見た目を base.css に取り込む

.work-tabs の指定を base.css に移し、全ページの共通デザインにする。

良い点
作業画面の下段タブの見た目が1か所にまとまる。
懸念点
.work-tabs は business_definition_sheet.html・business_flow.html・calenderschedule.html・object_model.html・outline.html・data_transition.html の6ページにあり、data_transition.html は書き方が少し違う。Issue #2 より範囲が大きい。

選択肢 C：独自の指定を範囲外へ移す

範囲内の独自の指定を、そのままページ固有のCSSへ移す。

良い点
指定を消さずに残せる。
懸念点
移した指定は .work-tabs の指定に上書きされて効いていないため、意味のないCSSが残る。

選択肢 D：現状維持

2ページは同期の対象外として扱う。

良い点
作業が発生しない。
懸念点
base.css の変更が2ページに届かず、--check が常に失敗する。
04 /

決定

DECISION

2ページの共通CSSの範囲にある独自の書き換えは取り除き、node bases/sync_styles.mjs で base.css と一致させる（選択肢 A）。タブの見た目は、範囲外のページ固有CSS（.work-tabs）で決める。

決定の理由

  • 基準 1：範囲内が base.css と一致し、今後の base.css の変更も2ページに届く。
  • 基準 2：同期の前後で、タブの表示が変わらないことを確認した（下記「確認した内容」）。
  • 基準 3：変更は2ページの範囲内だけで、スクリプトの実行で済む。
  • 選択肢 Bは、6ページにまたがる別の共通化で、Issue #2 の範囲を超えるため、ここでは選ばない（「見直しの条件」に記載）。
  • 選択肢 Cは、効いていない指定を残すことになるため選ばない。
  • 選択肢 Dは、共通デザインの仕組みから外れたままになるため選ばない。

確認した内容

リポジトリのコピーで2ページを同期し、同期前と同期後をヘッドレスのGoogle Chromeで描画して、スクリーンショットを比べた。

ページ状態画面幅結果
business_definition_sheet.html初期表示（整理項目タブを選択）1440px・700px完全に同じ
business_definition_sheet.htmlシートのタブを選択1440px完全に同じ
outline.html初期表示（タブ1つ）1440px・700px完全に同じ
outline.htmlタブを追加して2つ目を選択1440px完全に同じ

選択中のシートタブの「×」にマウスを乗せたときの色は、スクリーンショットでは比べられないため、CSSの優先順位で確認した。範囲内の .sheet-tab:has([aria-selected="true"]) .delete-tab:hover と範囲外の .work-tabs .work-tab-item .work-tab-delete:hover は詳細度が同じで、範囲外のほうが後ろにあるため、範囲外の指定が使われる。

05 /

結果・影響

良い影響

  • 2ページにも base.css の変更が届き、デザインの共通化ができる。
  • node bases/sync_styles.mjs --check が「すべてのHTMLに反映済みです。」になり、反映漏れの確認に使える。

受け入れる不利益

  • 作業画面の下段タブの見た目（.work-tabs）は、6ページの範囲外に重複して書かれたまま残る。

その他の影響

  • 再発を防ぐため、AGENTS.md に「共通CSSの範囲は直接編集せず、作業の最後に node bases/sync_styles.mjs --check を実行する」ルールを追加した。
