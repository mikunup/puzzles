ADR-0008：bases/ の基準をMarkdownに要約し、AIはまずそれを読む

bases/ のHTMLの要点を bases/README.md にまとめ、AIはデザインの基準をまずこのMarkdownから読む。HTMLは見本の見た目や操作を確かめるときだけ読み、HTMLや base.css を変えたら同じ作業で要約も直す。

01 /

背景・課題

bases/ は、新しい画面を作るときや既存画面を整えるときに参照するデザイン・レイアウトの基準である。AIが画面を作るたびに、この基準を読む必要がある。

現状

  • 基準はHTML3ページ（display.html・atomic_component.html・color.html）で、合わせて約17万バイトある。
  • 大半は埋め込み画像・CSS・JavaScript・見本の装飾で、基準として読む必要がある文章は一部だけである。
  • 表示用のHTMLなので、AIが必要な情報（色の値・タブの決まり・キー操作など）を探すのに手間がかかる。

制約・前提

  • 各HTMLは1ファイルで動く、見て学ぶ資料として残す。
  • AIのトークン量を減らす方針（ADR-0005）を続ける。
  • 外部パッケージは使わない（ADR-0003）。
この ADR で決めることAIが bases/ の基準を、少ないトークンで正しく読むにはどうするか。
02 /

判断基準

  1. AIのトークン量を減らせること

    画面を作るたびに読む資料なので、効果が大きい。

  2. HTMLと内容がずれないこと

    要約が古いと、AIが誤った基準で画面を作る。

  3. 手間が増えすぎないこと

    基準を変えるときの作業を大きく増やさない。

03 /

検討した選択肢

判断基準選択肢 A：手で書いた要約Markdown採用選択肢 B：HTMLから自動で抽出選択肢 C：現状維持
トークン量を減らせる◎要点だけで約8.6千バイト（HTMLの約5%）○見本の文言や重複も残る×毎回HTMLを読む
HTMLとずれない△直し忘れのおそれがある◎生成するのでずれない◎元を直接読む
手間が増えすぎない○基準を変えたときだけ要約も直す△抽出スクリプトの作成と保守が要る◎何も増えない

◎：基準を十分に満たす　○：満たす　△：課題がある　×：満たさない

選択肢ごとの詳細

選択肢 A：手で書いた要約Markdown

bases/README.md に、実装ルール・配色・部品・タブ・Vim操作・画面の幅・記号の意味を表とリストでまとめる。AGENTS.md に「まず要約を読む」「基準を変えたら要約も直す」ルールを置く。

良い点
必要な情報だけを、AIが探しやすい形で読める。GitHubでもディレクトリを開くと表示される。
懸念点
HTMLを変えたときに要約の直し忘れが起きうる。

選択肢 B：HTMLから自動で抽出

スクリプトでHTMLから本文を取り出し、Markdownを生成する。

良い点
要約がHTMLとずれない。
懸念点
見本の文言や説明用の注記まで残り、要約ほど短くならない。抽出の決まりを保守する必要がある。

選択肢 C：現状維持

AIは毎回 bases/ のHTMLを読む。

良い点
作業が増えない。
懸念点
トークン量が多いまま残る。
04 /

決定

DECISION

bases/ の基準の要点を bases/README.md に手で要約し、AIはまずこのファイルを読む。HTMLや base.css の内容を変えたら、同じ作業で要約も直す（選択肢 A）。

決定の理由

  • 基準 1：読む量が約17万バイトから約8.6千バイトに減る。
  • 基準 3：基準を変えるのはまれで、そのときに要約を直す手間は小さい。
  • 基準 2の懸念は、AGENTS.md のルールで同じ作業の中で直すことにして抑える。
  • 選択肢 Bは、要約ほど短くならず、スクリプトの保守も増えるため選ばなかった。
  • 選択肢 Cは、トークン量が減らないため選ばなかった。
05 /

結果・影響

良い影響

  • AIが画面を作るときに読むトークン量が大きく減る。
  • 色の値・タブの決まり・キー操作などを1か所で確認できる。

受け入れる不利益

  • 要約とHTMLの2か所を直す必要があり、直し忘れると内容がずれる。

その他の影響

  • AGENTS.md に「デザインの基準は bases/README.md から読む」ルールを追加した。
  • bases/ のHTMLの見た目と、sync_styles.mjs の動きは変わらない。
06 /

確認と見直し

確認する指標

AIが画面を作るときに、bases/ のHTMLを読まずに基準どおりの画面を作れていること。

見直しの条件・時期

要約とHTMLのずれが見つかることが多い場合は、選択肢 B（自動での抽出）や確認スクリプトを検討する。
