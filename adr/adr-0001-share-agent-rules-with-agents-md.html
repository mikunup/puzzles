01 /

背景・課題

変更のたびに adr/ 配下へMarkdownとHTMLのADRを作るルールを、CLAUDE.md に定めた。このリポジトリではClaude Codeに加えてCodexも使う予定だが、Codexが自動で読むのは AGENTS.md で、CLAUDE.md は読まない。このままでは、Codexで作業したときにADRのルールが適用されない。

現状

  • ルールは CLAUDE.md にだけ書かれている。
  • Claude Codeは CLAUDE.md を読むが、Codexは読まない。

制約・前提

  • リポジトリをクローンした別の環境でも、追加の設定なしでルールが効くこと。
  • ルールを書く場所は1か所にし、ツールごとに内容がずれないようにすること。
  • 主にmacOSで使うが、Windowsでも壊れない構成にすること。
この ADR で決めることClaude CodeとCodexの両方に同じルールを読ませるには、ルールをどのファイルに置き、どうつなげるか。
02 /

判断基準

  1. 両方のツールで同じルールが読まれること

    ツールによってADRが作られたり作られなかったりすると、変更の記録が欠けるため。

  2. ルールを書く場所が1か所であること

    2つのファイルを手で揃える運用では、片方だけ更新されて内容がずれるため。

  3. 利用する環境に依存しないこと

    PCごとの設定やOSの違いで、ルールが読まれなくなるのを避けるため。

03 /

選択肢ごとの詳細

選択肢 A：AGENTS.mdに本体、CLAUDE.mdから取り込む

ルールを AGENTS.md に書き、CLAUDE.md は @AGENTS.md の1行だけにする。Claude Codeは @ で指定したファイルを取り込む。

良い点
両ツールが標準の仕組みで同じ内容を読む。リポジトリ内で完結する。
懸念点
CLAUDE.md に直接ルールを書き足すと、Codexには伝わらない。

選択肢 B：シンボリックリンク

ルールを CLAUDE.md に書き、AGENTS.md をそのシンボリックリンクにする。

良い点
実体が1つなので、内容が必ず一致する。
懸念点
Windowsやgitの設定によっては、リンクがパスを書いた通常のファイルとして取り出される。

選択肢 C：Codexの設定でCLAUDE.mdを読ませる

~/.codex/config.toml の project_doc_fallback_filenames に CLAUDE.md を加える。

良い点
リポジトリのファイルを変えずに済む。
懸念点
設定はPCごとで、クローンした他の環境には効かない。設定項目はCodexのバージョンで変わる可能性がある。

選択肢 D：現状維持

CLAUDE.md だけにルールを書いたままにする。

良い点
作業が発生しない。
懸念点
Codexで作業したときにADRのルールが適用されない。
04 /

決定

DECISION

AIエージェント向けのルールの本体をリポジトリ直下の AGENTS.md に置き、CLAUDE.md は @AGENTS.md の1行で取り込む（選択肢 A）。

決定の理由

判断基準の3つすべてを満たすのは選択肢 Aだけだった。

  • 基準 1：Claude CodeとCodexの両方が、それぞれ標準の仕組みで同じルールを読む。
  • 基準 2・3：ルールの本体は AGENTS.md の1か所で、リポジトリ内で完結する。
  • 選択肢 Bは、Windowsでリンクが壊れる可能性があるため選ばなかった。
  • 選択肢 Cは、PCごとの設定が必要でクローンした環境に効かないため選ばなかった。
  • 選択肢 Dは、Codexでルールが適用されないため選ばなかった。
05 /

結果・影響

良い影響

  • Claude CodeとCodexで、同じルールに沿って作業できる。
  • ルールの追加・変更は AGENTS.md だけを編集すればよい。

受け入れる不利益

  • CLAUDE.md に直接ルールを書いてもCodexには伝わらない。ルールは必ず AGENTS.md に書く必要がある（AGENTS.md の冒頭に明記した）。
  • Claude Codeの @ による取り込み機能に依存する。

その他の影響

  • AGENTS.md を読む他のAIツールにも、同じルールが伝わる。
  • これまで CLAUDE.md にあったルールは、AGENTS.md に移した。
