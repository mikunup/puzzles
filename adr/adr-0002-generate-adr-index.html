ADR-0002：ADR一覧をスクリプトで生成し、MarkdownとHTMLで提供する

ADRの一覧を adr/README.md と adr/index.html に置き、一覧部分は adr/build_index.mjs が各ADRのMarkdownから生成する。

01 /

背景・課題

ADR-0001で、変更のたびに adr/ 配下へMarkdownとHTMLのADRを1組作るルールを決めた。変更のたびにADRが増えるため、どんな決定があるかを一覧で確認し、件数が増えても目的のADRを探せる仕組みが必要になった。

現状

  • adr/ 配下にADRが1件あるが、一覧はない。
  • ADRは変更のたびに増え、ステータスも「提案中」から「承認」「置換」などへ変わる。

制約・前提

  • リポジトリの他のHTMLと同じく、HTMLは1ファイル単独で表示・操作でき、外部に依存しないこと。
  • ブラウザでHTMLファイルを直接開いて（file://）使えること。
  • ADRと同じく、一覧もMarkdownとHTMLの両方で読めること。
この ADR で決めることADRの一覧をどこに置き、件数が増えても内容がずれず探しやすい状態をどう保つか。
02 /

判断基準

  1. 一覧がADR本体とずれないこと

    一覧のステータスやタイトルが本体と違うと、一覧を信用できなくなるため。

  2. 件数が増えても探せること

    変更のたびにADRが増えるため、番号順の表だけでは目的のADRにたどり着きにくくなる。

  3. HTML単体で動き、外部に依存しないこと

    リポジトリの他のHTMLと同じ方針で、ファイルを開くだけで使えるようにするため。

03 /

検討した選択肢

判断基準選択肢 A：スクリプトで生成採用選択肢 B：手で一覧を更新選択肢 C：HTMLがADRを読み込んで表示選択肢 D：一覧を作らない

選択肢ごとの詳細

選択肢 A：スクリプトで生成

adr/build_index.mjs が adr/adr-NNNN-*.md を読み、見出し・要約・ステータス・決定日・対象範囲を取り出して、README.md と index.html のマーカーの間を書き換える。スクリプトはNode.jsで書き、外部パッケージは使わない。

良い点
MarkdownとHTMLの一覧が同じ元データから作られる。ファイル名・番号の重複・対になるHTMLの有無・ステータスの表記をまとめて検査できる。
懸念点
ADRを追加・更新したあとにスクリプトの実行が必要。ADRのMarkdownの書式に依存する。

選択肢 B：手で一覧を更新

ADRを作るたびに、README.md と index.html の表へ1行ずつ手で追加する。

良い点
仕組みが不要で、すぐに始められる。
懸念点
MarkdownとHTMLの2か所を手で揃える必要があり、ステータス変更の反映漏れが起きやすい。

選択肢 C：HTMLがADRを読み込んで表示

index.html がJavaScriptで各ADRのファイルを読み込み、一覧を組み立てる。

良い点
スクリプトを実行しなくても、開くたびに最新の一覧になる。
懸念点
ブラウザでファイルを直接開いた場合（file://）、他のファイルを読み込めない。Markdown版の一覧は別に必要になる。

選択肢 D：一覧を作らない

GitHubやエディタのファイル一覧で adr/ を見る。

良い点
作業が発生しない。
懸念点
タイトルやステータスがファイルを開かないとわからず、件数が増えると探せない。
04 /

決定

DECISION

ADRの一覧を adr/README.md と adr/index.html に置き、一覧部分は adr/build_index.mjs が各ADRのMarkdownから生成する（選択肢 A）。

決定の理由

判断基準の3つすべてを満たすのは選択肢 Aだけだった。

  • 基準 1：一覧はADR本体から生成し、--check で一覧が古くなっていないかを確認できる。
  • 基準 2：HTML版はキーワード検索・ステータスでの絞り込み・並べ替えに対応し、件数が増えても探せる。
  • 基準 3：生成した行をHTMLに埋め込むため、ファイルを開くだけで動く。
  • 選択肢 Bは、2か所を手で揃える必要があり、ずれが起きやすいため選ばなかった。
  • 選択肢 Cは、file:// で開いたときに動かないため選ばなかった。
  • 選択肢 Dは、件数が増えると探せないため選ばなかった。
05 /

結果・影響

良い影響

  • ADRを追加したら node adr/build_index.mjs を実行するだけで、MarkdownとHTMLの一覧が揃う。
  • ファイル名の形式・番号の重複・HTMLの作り忘れ・ステータスの表記ゆれを、実行時にエラーとして検出できる。
  • スクリプトが次に使う番号を表示するため、番号の付け間違いを防げる。

受け入れる不利益

  • スクリプトの実行を忘れると、一覧が古いままになる（--check で検出できる）。
  • 一覧はADRのMarkdownの書式（見出し・> で始まる要約・ステータスなどの表）に依存する。書式を崩すとエラーになる。
  • 一覧の情報はMarkdown版から取り出す。HTML版だけを直しても一覧には反映されない。

その他の影響

  • AGENTS.md のADRルールに、一覧の更新手順を追加した。
  • README.md と index.html のマーカー（adr:index:start〜adr:index:end）の間は手で編集しない。

確認する指標

ADRを追加・更新したあとに node adr/build_index.mjs --check を実行し、常に「一覧は最新です。」と表示されること。

見直しの条件・時期

ADRが100件程度を超えて一覧が見づらくなった場合は、年やステータスでの分割を検討する。各ADRのHTMLをMarkdownから自動生成する仕組みを作る場合は、このスクリプトと統合する。
