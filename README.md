# puzzles — 業務・画面設計の資料とツール

業務の整理、オブジェクト設計、画面設計・テスト、計画づくりに使うHTMLをまとめています。各リンクは別タブで開く指定にしています。

<a href="README.html" target="_blank" rel="noopener noreferrer">HTML版の資料一覧を開く ↗</a>

## 使い始める

1. `README.html`をブラウザで開き、目的に合う資料を選びます。
2. 業務定義 → 業務フロー → オブジェクト整理 → 画面設計 → 画面単体テストの順で、情報を具体化できます。
3. 業務フロー図で整理した後、カレンダーで作業名・担当・開始日・完了予定日を登録し、月・週ごとの完了予定と実績を確認します。スケジュール計画書はプロジェクト全体の計画に使います。

### ドメインからシステムを設計する

業務の整理から一歩進めて、システムが担う責務を決め、サブドメインごとに分けて解決し、機能に落とし込むための資料です。最初に使い方を読み、上から順に書きます。

1. **使い方を読む**：資料の層と使い方（doc_layers.html）で、各層の関係と、コンテキストの分け方を確認します。
2. **ドメイン定義書（システムで1つ）**：システムがまたがるドメインとサブドメイン、システムの責務（RESP）を洗い出し、解決するコンテキストを決めます。

## 共通デザインの適用

全19ページは、各HTMLファイル1つで表示・操作できる構成です。CSS・JavaScript・表示に必要な画像はHTML内に含め、外部の共通CSSなどには依存しません。配色・フォーカス表示・タブの選択表示は`bases/`の基準に合わせています。実装ルールは[bases/display.html](bases/display.html)を参照してください。資料間のリンクや、利用者が選んで読み込むJSONは別ファイルとして扱います。

共通スタイルの編集元は`bases/base.css`です。変更後はリポジトリ直下で次を実行すると、全HTMLの埋め込みCSSを直接更新できます。

```sh
python3 bases/sync_styles.py
```

保存のたびに自動反映する場合は`python3 bases/sync_styles.py --watch`（Ctrl+Cで終了）、反映漏れを確認する場合は`python3 bases/sync_styles.py --check`を使います。確認モードは未反映があると終了コード1を返します。共通CSSの範囲（`<!-- bases:styles:start -->`〜`<!-- bases:styles:end -->`）は同期で上書きされるため、共通変更は`base.css`を編集し、ページ固有のCSSは範囲外に記述してください。新規HTMLにも、この開始・終了マーカーを1組配置してください。

- **編集画面**：業務フロー図・カレンダー・オブジェクト整理・アウトライン・データ遷移は全幅の作業領域を使います。業務定義シート・スケジュール計画書も画面幅を活かして表示します。
- **資料画面**：資料一覧・説明資料の雛形・ADR・ドメイン定義書・コンテキスト定義書・機能仕様書の雛形とその使い方・画面設計書・画面単体テストは、本文の領域を最大1440pxのレイアウト内で広く確保し、狭い画面では目次と本文を縦に並べます。
- **タブ操作**：タブにフォーカスした状態で左右矢印・Home・Endを使えます。業務定義シートはシート、カレンダーは表示方法、業務フロー図・オブジェクト整理・アウトラインは作業を切り替えます。
- **Vim操作・集中表示・全画面**：業務フロー図・カレンダー・オブジェクト整理・アウトライン・データ遷移で利用できます。キーの意味は各ページの操作ヘルプを確認してください。アウトラインのパネル開閉はパネル見出し（OUTLINE / 見取り図）の横から操作できます。
- **印刷**：画面用の幅変更は印刷に適用せず、各ページの印刷用レイアウトを使用します。

## 編集と保存

- **編集ツールのページ**：業務定義シート・業務フロー図・オブジェクト整理・データ遷移・カレンダー・アウトラインでは、画面内で内容を入力します。
- **資料のページ**：画面設計書・スケジュール計画書・説明資料・ADR・ドメイン定義書・コンテキスト定義書・機能仕様書の雛形は、HTML内の文章や表を書き換えて使います。
- **テストの記録**：画面単体テストケースは、画面内で実施結果とメモを入力できます。
- **ブラウザ内の保存**：データは端末間で自動共有されず、HTMLファイル自体にも書き戻されません。別のブラウザや保存場所では同じ記録を参照できない場合があります。
- **書き出し**：JSON機能があるページでは、データの受け渡しや控えに書き出しを使います。読み込み機能の有無は各ページのボタンを確認してください。

## 業務タスクの完了予定（カレンダー）

1. `business_flow.html`で作業の流れを整理します。
2. `calenderschedule.html`に作業名・担当・前工程を登録し、開始日と完了予定日を割り当てます。作業名などは手動で登録します。
3. 「月のタスク」で全体、「週のタスク」で直近の完了予定を確認します。帯は作業期間、◆は完了予定日を示します。右の一覧も完了予定日順です。
4. 状態を未着手・作業中・完了から選び、完了時には実際の完了日を記録します。件数の集計や、現在日による予定日超過の判定は表示せず、参考月の作業期間・完了予定日・担当・前工程の可視化に使います。初期表示は最初のタスクがある月・週です。

入力欄の外では`j/k`でタスク選択、`h/l`で月・週移動、`t/Shift+t`で表示タブ切り替え、`i`で追加、`e`で編集、`o`で選択タスクに集中、`f`で全画面表示ができます。補助パネルの「完了予定」は開閉できます。保存先は従来と同じブラウザで、既存の予定も引き続き表示します。状態がない既存データは未着手として扱います。

## ローカルデータの管理

- **`datas/`**：ローカルにダウンロードしたJSONや、各ツールから書き出したデータなどを追加して保存・管理するディレクトリです。必要に応じて、各ページのJSON読み込み機能で利用します。
- **`.gitignore`**：Gitの管理対象から除外するパスを指定するファイルです。`/datas/`を指定し、このリポジトリ直下の`datas/`とその配下のファイル・サブディレクトリを除外しています。
- `datas/`内のデータはコミット・共有されません。新しくクローンした環境では、必要に応じて`datas/`を作成し、データを配置してください。このREADMEの`datas/`へのリンクは、対応するファイルをローカルに配置した場合に利用できます。

## 業務フロー図のオブジェクト

- 右側には未配置のオブジェクトだけを表示します。ドラッグすると、同じIDのままマスへ移動します。
- 「配置を解除」はオブジェクトを未配置へ戻し、その接続線を外します。「元に戻す」で配置と線を復元できます。
- 「複製」は別IDの未配置オブジェクトを作ります。「完全に削除」はオブジェクトと接続線を削除します。
- JSONは`schemaVersion: 2`で、`objects`がすべてのオブジェクトを保持します。`placement: null`は未配置、`placement: { "row": "行ID", "col": "列ID" }`は配置済みです。`edges.from`と`edges.to`はオブジェクトIDを参照します。
- 旧形式の`library`・`nodes`も読み込めます。同じ元項目を複数配置していた場合は、配置ごとに独立したオブジェクトへ移行し、矢印の対応を引き継ぎます。

## 作成済みの業務フロー

- `business_flow.html`を再読み込みすると、営業アシ → 営業 → 経理 → 営業 → お客様の「請求書の発行」タブを一度だけ追加します。
- [invoice_issue_flow.json](datas/invoice_issue_flow.json)は、このフロー単体のJSONです。JSON読み込みで現在のタブへ取り込むこともできます。
- 「請求書の発行（情報単位）」も別タブとして一度だけ追加します。行を「受注データ・請求データ・請求書」の3つにまとめ、作成・確認・確定などは作業と矢印で表します。[JSONはこちら](datas/invoice_issue_flow_information.json)。
- 状態別の行は進行・承認の段階を確認する場合、情報単位の行は同じデータが担当間をどう渡るかを見る場合に使い分けます。

## オブジェクト整理の操作

- コレクションは1枚のカードで、元のオブジェクト選択・表示項目・操作・プレビューを設定します。元はチップで表示し、「−」で外せます。操作は「一覧全体」と「1件ごと」にまとめています。
- `object_model.html`は「オブジェクト」「関係図」「関係一覧」を切り替えられます。参照型プロパティの設定から図と表を自動更新します。
- 関係一覧には、参照元×参照先のマトリクス、参照プロパティごとの一覧、コレクションの構成を表示します。表の名前やプロパティをクリックすると編集箇所へ移動します。多重度は推測しません。
- 入力欄からEscで抜けると、`j/k`で項目移動、`h/l`で参照元／先へ移動、`i`でオブジェクト追加、`Shift+i`でコレクション追加、`e`で編集、`z`で開閉、`o`で集中表示、`f`で全画面、`v`で表示切替ができます。
- 下部のタブは「＋」で追加、「−」で削除し、`t/Shift+t`で切り替えます。モデル・表示・折りたたみ・選択状態をタブごとに保存します。`u/Ctrl+r`の編集履歴はタブごとに保持し、再読み込みするとリセットされます。
- 従来のversion 3 JSONはそのまま読み込めます。「このタブをJSON保存」は同じ形式、「全タブをJSON保存」はモデル名と表示状態を含むタブ全体の形式です。以前のブラウザ内データは最初のタブに引き継ぎます。

## Enum型のプロパティ

プロパティの種類で「Enum（列挙型）」を選び、「＋ 候補」で保存値と表示名を追加します。候補の入力はEnterまたはフォーカスを外した時に確定します。保存値は同じプロパティ内で重複できず、保存値・表示名を空欄にした場合は元に戻します。

初期値は候補から選択でき、未指定にもできます。保存値を変更すると初期値も追従し、初期値の候補を削除すると未指定へ戻ります。別の型に切り替えてもEnumの設定は保持します。

```json
{
  "id": "invoice-status",
  "name": "状態",
  "type": "enum",
  "ref": "",
  "enumValues": [
    { "value": "draft", "label": "作成中" },
    { "value": "issued", "label": "発行済み" }
  ],
  "defaultValue": "draft"
}
```

単一モデル・全タブのJSON保存に含まれます。コレクションのプレビューは初期値の表示名を使用し、初期値がない場合は最初の候補を例として表示します。Enumは状態の候補を定義するもので、状態遷移の条件や操作の実行は別の設計です。従来の`select`型や候補を持たない既存JSONも引き続き読み込めます。

## 請求業務のオブジェクト設計

[invoice_object_model.json](datas/invoice_object_model.json)を`object_model.html`の「JSON読み込み」で選ぶと、受注情報・請求情報・請求書情報・営業・経理・お客様・営業アシの7オブジェクトと、それぞれの一覧を読み込めます。作成者・確認者・確定者・請求先・送付先などを参照型で関連付けています。状態はEnum型のプロパティとして持ち、保存値・表示名・初期値をJSONと画面の候補欄に定義しています。遷移・担当は各オブジェクトの説明欄に記載しています。

元の業務フローで確定するのは請求情報です。請求書側の確定・発行を独立した段階として設けることは追加の設計案であり、実行者・条件の確認が必要です。プロパティも設計候補として記載しています。
