01 /

解決する領域

SUBDOMAIN

［このコンテキストが解決するサブドメインを1文で言い切ります。例：「注文を正しく受け付け、確定する。」ドメイン定義書 04 の「解決すること」と揃えます。］

1対1でない場合［サブドメインを分割したコンテキストなら、サブドメインのどの部分を担うかと、同じサブドメインを分け合う相手のコンテキストを書きます。例：「在庫サブドメインのうち、販売の引き当てを担う。倉庫での入出庫は倉庫在庫コンテキストが担う。」複数のサブドメインを統合したコンテキストなら、含むサブドメインをすべて書き、コードのモジュールをサブドメインごとに分けているかを書きます。どちらの場合も、理由を記録した ADR へリンクします。1対1のときは、この枠を削除します。］

担う責務

［ドメイン定義書 03 の責務のうち、このコンテキストが担うものを記載します。ここにない責務は、このコンテキストでは実装しません。］

責務 ID責務このコンテキストでの実現のしかた

RESP-00x［責務］［実現のしかた］

含むもの

ユビキタス言語

［このコンテキストの中で、業務担当者と開発者が共通で使う用語を定義します。会話・画面・コード・データベースで同じ言葉を使います。用語の意味はここが正本です。他のコンテキストで意味が変わる用語は、ドメイン定義書 06 に用語名だけを載せ、意味は書き写しません。業務モデル・仕様書・Catalog も、ここの名前を使います。］

用語英語名・コード上の名前意味使わない言い方・注意
［用語 A］［EnglishName］［このコンテキストでの意味。1〜2文で言い切ります。］［「〜」とは呼ばない。「〜」との違い。］
［用語 B］［EnglishName］［意味］［注意］
［用語 C］［EnglishName］［意味］［注意］

04 /

ビジネスルール

［このコンテキストで守る業務上の決まりごとを、1行に1つずつ記載します。入力できる値の範囲や、選べるものの条件など、業務担当者が説明できるバリデーションもここに書きます。ここが正本で、Objects・仕様書・Catalog は RULE 番号で参照します。「いつ」「何が」「どうなる」が読み取れる文にし、根拠（法令・社内規程・経営判断）を添えます。］

IDルール適用される場面違反したときの扱い根拠
RULE-001［例：注文の合計金額が［金額］以上のとき、承認者の承認を必要とする。］［注文確定時］［確定できない。承認待ちにする。］［社内規程 第○条］
RULE-002［例：状態が「確定」の注文は、明細を変更できない。］［明細の変更時］［変更を受け付けない。］［受注業務規程］
RULE-003［例：注文の明細は1件以上とする。］［明細の削除時・注文確定時］［最後の1件は削除できない。］［業務上の前提］
RULE-004［例：注文明細の数量は 1 以上 999 以下とする。］［明細の追加・変更時］［受け付けない。］［受注業務規程（1回の注文の上限）］
RULE-005［例：注文明細に選べる商品は、販売中の商品に限る。］［明細の追加・変更時］［受け付けない。］［販売方針］
例外・判断が必要なケース［ルールで決めきれず、人が判断する場面と、判断する人を記載します。］
05 /

状態とライフサイクル

［主要な概念がどの状態を経るかを要約として記載します。状態ごとに「次に進める状態」と「進むための条件・操作」を書くと、機能仕様書の前提やテストケースに展開できます。誰がどの作業・帳票で状態を進めるかは、業務フロー図に書きます。］

状態意味遷移先遷移する条件・操作この状態でできること
［下書き］［入力中。まだ業務上の効力がない］［確定 / 取消］［「確定」操作。RULE-001 を満たすこと］［明細の追加・変更・削除］
［確定］［意味］［出荷済 / 取消］［条件・操作］［できること］
［取消］［意味］—［条件・操作］［参照のみ］

誰がどの作業・帳票で状態を進めるかは、業務フロー図のこのコンテキストのタブに書きます。行のステータスには、この表の状態名をそのまま使います。

07 /

連携

［このコンテキストが他のコンテキスト・外部システムに提供するもの、利用するものを、業務の言葉で記載します。関係パターンはドメイン定義書 05 を正本とし、ここには書きません。エンドポイントや入出力の定義は Catalog の API 定義に書き、ここからリンクします。変更するときに誰と調整するかも決めておきます。］

方向相手種類名前・内容変更時の調整
提供［在庫・請求］［イベント］［注文が確定した（中身は 06）］［項目の削除は利用先の合意を得る］
利用［在庫］［API］［在庫数の照会：SKU ごとの販売可能数（定義は Catalog の API 定義）］［在庫チームに版の変更予定を確認する］
利用［認証（外部サービス）］［API］［トークンの検証］［外部の仕様変更に合わせる］
